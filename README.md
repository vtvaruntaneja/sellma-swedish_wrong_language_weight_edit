# Wrong-language replies to Swedish prompts: does a small weight edit fix them?

A take-home for SE.LLMA (WASP). It has two parts:

1. A critique of the blog post
   ["Sparks of Weight-Space Programming"](https://rikiyat.github.io/blog/weight-space-programming/):
   `results/critique_own.md`, then `results/critique_comparison.md` (comparison with the researcher's notes).
2. A small experiment. A feedback-guided, activation-derived weight edit is applied to Qwen2.5-0.5B-Instruct to
   stop it replying in Norwegian, Danish or English to Swedish prompts. The edit is compared with:
   - random edits of the same size;
   - a Swedish system prompt;
   - an empty system prompt;
   - the repo's sampling settings;
   - a small LoRA fine-tune.

   It is the kind of edit the blog's Experiment 8 used. It is derived from activations and chosen with dev
   feedback, not read off the weights.

Write-up: `NOTE.md` (short research note), `report.pdf` (longer version), `AI_USAGE.md` (what the AI tools did).
All numbers: `results/summary.md` and `results/summary.json`, generated by `analyze.py`.

## Reproduce

Needs an Apple-silicon Mac with MPS and Python 3.11 (versions pinned in `requirements.txt`). Then run:

```
./run.sh            # everything, writes results/
./run.sh --quick    # smoke test: 10 dev prompts per set, writes results_quick/, never reads a test file
```

`run.sh` runs these steps in order:

| Step | What it does | Main outputs |
|---|---|---|
| `data.py` | builds `data/` from `data/source/*.tsv` and wikimedia/wikipedia | `data/*.jsonl` |
| `experiment.py langid` | lingua accuracy on labelled paragraphs (sv, no, da, en) | `langid_check_summary.json` |
| `experiment.py pilot` | 40 Swedish dev prompts, Qwen3.5-0.8B and Qwen2.5-0.5B-Instruct | `pilot_*_summary.json` |
| `experiment.py dev128` | dev round 1 (128 tokens): base run, Swedish-minus-English direction, 8 settings | `dev_selection.json` |
| `experiment.py base512` | base model on dev prompts at 512 tokens, compared with 128 | `dev512_base_summary.json` |
| `experiment.py dev512` | dev round 2: 8 settings, selection rule, English check, diagnostics | `dev512_selection.json`, `dev512_diagnostics.json` |
| `experiment.py lora --skip-dev-eval` | LoRA baseline trained on dev prompts only, without its own dev evaluation | `lora_summary.json`, `lora_adapter/` |
| `experiment.py test` | every condition on the test sets, once | `test_*.jsonl`, `test_config.json` |
| `analyze.py sheet` | blinded sheet for the hand annotation | `understanding_sheet.jsonl` |
| `analyze.py` | metrics, paired tests, examples | `summary.json`, `summary.md`, `examples.md` |
| `analyze.py note` | fills the results tables in `NOTE.md` | `NOTE.md` |

**One step is manual.** `results/understanding_labels.jsonl` is a hand annotation, not code output. For each
non-Swedish reply, it records whether the reply understood the prompt and whether lingua's language label is right.
It was written by Claude, following `results/understanding_rubric.md`. A fresh run of `analyze.py sheet` gives the
same items when the replies are identical.

If a run is interrupted, `--resume` reuses generation files that already hold every item.

## Files

- `common.py`: model loading, generation, language identification, activations, the weight edit, scoring.
- `experiment.py`: the experiment steps listed above.
- `analyze.py`: metrics, statistics, tables, examples, the annotation sheet.
- `data.py`: builds `data/`.
- `data/source/`: hand-written prompts and questions.
- `data/`: the dev and test sets as built.
- `results/`: every output, config and summary, including model revisions, seeds, settings and the feedback budget.

## Deviations from the original plan

All of these are also in `NOTE.md` and `AI_USAGE.md`.

- **Model.** Qwen3.5-0.8B replied in Swedish to all 40 pilot prompts, so the plan's fallback model was used.
- **Pilot decoding.** The Qwen2.5 pilot ran greedy decoding with the repo's default `repetition_penalty=1.1`. All
  later runs use pure greedy decoding (1.0).
- **Dev round 1 and round 2.** Round 1 ran as planned, with 128 tokens and the plan's fallback direction, because
  there were 18 failures, fewer than 20. Removing that direction cannot make replies more Swedish. So the
  researcher chose round 2: 512 tokens, the two-halves language rule, multiplying the Swedish-minus-English
  component, and removing or flipping the failure direction. The feedback budget counts both rounds.
- **Test-set use.** The first `--quick` version read the first 10 items of every test file. The main analysis
  leaves those items out. `--quick` now uses dev files only.
- **Random control.** 5 random directions instead of 3, decided before the test run.
- **LoRA dev evaluation not run.** After training and saving the adapter, the LoRA process stalled with memory full
  (14 GB footprint, swap nearly full) during its dev evaluation, and was killed. Training had finished: all 54
  steps are logged and the adapter was saved afterwards. `results/lora_summary.json` was therefore written by hand
  from the step log, the adapter and the file times, and it says so. `run.sh` passes `--skip-dev-eval` so that the
  code matches what was run. On a 16 GB Mac, LoRA training at 512 tokens took up to 82 minutes.
